# iPad2,6 (p106ap): the GSM iPad mini 1

The port was written on the Wi-Fi model, iPad2,5 (p105ap).  The GSM model,
iPad2,6 (p106ap), is the same board plus a modem, and builds from this tree
with one setting:

```sh
echo p106 > .board          # or BOARD=p106 on each command
curl -LO 'https://secure-appldnld.apple.com/ios8.4.1/031-31278-20150812-751FA1F8-3C8F-11E5-9856-BF1A3A53DB92/iPad2,6_8.4.1_12H321_Restore.ipsw'
./cascadia firmware
./cascadia build
```

Everything else in the QUICKSTART is the same.  `scripts/board.sh` holds the
per-board values.

## Why the same port fits

Compared on Apple's own 12H321 (iOS 8.4.1) images of both boards:

**iBSS and iBEC.**  The same iBoot-2261.30.37, the same size, the same code.
They differ in:

- the board name (`p105` → `p106`);
- one ID byte in iBSS (`0xfe14`: `0xb9` → `0xba`);
- the two GPIO pad tables iBEC picks between in the function at `0x9ff20e30`
  (`0x9ff42cf4` and `0x9ff43034`; iBSS has the same pair);
- iBEC's build hash at `0x43a3c`.

`scripts/patch-ibec-autogo.py` therefore applies unchanged.  `HOOK_OFF` holds
the same `1a480121`, the trampoline area is just as empty, and the helpers it
calls are at the same addresses.

**Pad tables.**  Seventeen pins differ.  All of them are `0x009e` (unused) on
p105:

| Pin (port.bit) | p106 use, from its ADT |
|---|---|
| 10, 12, 13, 15, 17, 23, 24 | modem: bb_rst, hsic_ready, remote_wake, reset_det, host_ready, radio_on, device_ready |
| 30 | unnamed |
| 128, 130 | uart4 tx, rts |
| 129, 131, 133–137 | unnamed (uart4 and modem, presumably) |

None of them is a pin this port uses (0–4, 9, 21, 22, 40–43, 50, 51, 63, 103).

**Apple Device Tree.**  With phandles resolved to node paths, the two trees
agree on every node the port describes: AIC, timers, GPIO, buttons, PMU,
charger, touch (p106 also says `multi-touch,p105`), Wi-Fi (module `borg`),
Bluetooth, audio, backlight, display, SGX and USB device.  p106 adds:

- `/baseband` (`baseband,n41`, chipset `mav5`);
- `arm-io/usb-complex/usb-ehci/hsic-baseband`;
- `arm-io/uart4/debug`;
- product flags (GPS, personal hotspot, FaceTime over 3G).

`dts/p106ap.dts` includes `dts/p105ap.dts` and changes only `compatible` and
`model`.  The modem is not described, and nothing powers it.

**Kernelcache.**  p106's has four more kexts: AppleBasebandN41,
AppleUSBHSICCellular, AppleEmbeddedProx and AppleIPAppender.  Everything
after them is prelinked further up; IMGSGX543 is at `+0x6000`.
`tools/sgx/mkpack.py` works on p105's addresses, so the GPU firmware always
comes from p105's kernelcache.  On p106, `./cascadia firmware` fetches that
one 9 MB file out of p105's IPSW with HTTP range requests
(`scripts/ipsw-member.py`), not the whole 1.5 GB.

## What `./cascadia firmware` gave on p106

Run on 2026-10-20 against Apple's iPad2,6 12H321 IPSW:

- **iBSS and iBEC.**  The same steps on p105's stock images reproduce
  `KNOWN_IBSS_MD5` and `KNOWN_IBEC_PLAIN_MD5` exactly.  p106's results differ
  from those in 61 bytes (iBSS) and 80 bytes (iBEC), the same counts as the
  stock images differ by.  The signature patch and the auto-go hook therefore
  land identically on both.

  | File | p106 MD5 |
  |---|---|
  | `iBSS.patched` | `6cb60375e03e513d1fffd0c65b17198f` |
  | `iBEC.autogo` | `c66479581b353b9b429da2900daaf183` |

  They are the references in `scripts/board.sh` since the first p106 booted
  from them.
- **Touch.**  p106's rootfs has `P106.mtprops` and no `P105.mtprops`.  Its
  bytes match `KNOWN_MTPROPS_MD5`.
- **Wi-Fi and Bluetooth.**  `borg.trx`, `borg-t-st.txt` and BlueTool's
  "Borg TDK" patchram, which matches the 12H321 sha256.
- **GL event program.**  p106's dyld cache has it at p105's offset, and its
  sha256 matches.

## Jailbreak and kDFU on iPad2,6 / iOS 9.3.6

Done on the first p106 with Carbon (Safari, no sideloading) and the
`iocaste untether` package from Cydia, then OpenSSH; `./cascadia flash --kdfu`
works from there.  Carbon can take several tries (reboots or a frozen screen
are failed attempts; force-restart and run it again).  Do not leave Cydia while
iocaste installs.

## Touch calibration without a jailbreak

`./cascadia mtcal` reads the panel's calibration from a jailbroken iOS.  The
same 1024 bytes are readable over plain lockdown: the device tree node's
`multi-touch-calibration` from

```sh
idevicediagnostics ioregentry multi-touch
```

matches `AppleMultitouchN1SPI`'s `Calibration Data` byte for byte.  Written to
`build/keep/lib/firmware/mtcal.bin`, it is what `mtcal` would have produced.

## iOS-side research tools

`tools/mtdump/` carries iOS 8.4.1 p105 kernel addresses.  `tools/mtcal.sh`
reads the IORegistry only and accepts both boards; `gpucap.sh` and
`shadercap.sh` still refuse p106.

## Wi-Fi and Bluetooth module maker

This is per unit, not per board.  The same Borg module comes from TDK or USI,
and the NVRAM and the Bluetooth patchram have to be that maker's.  The
defaults are the author's p105 (TDK).  iOS names the module, no jailbreak
needed:

```sh
idevicediagnostics ioregentry AppleBCMWLANCore | grep -A1 ModuleInfo
```

The first p106 tried reports `M=HEIN m=3.5 V=u`, vendor USI, so its
`device.env` (read by `./cascadia`, not tracked) says:

```sh
WIFI_NVRAM=borg-u-st.txt
BT_MODULE="Borg USI"
```

`./cascadia firmware` hands both to the build container.  Before this, a
`WIFI_NVRAM=` on the command line never reached the container.

## First boot findings (2026-10-21)

- Linux came up on the iPad2,6 and the USB gadget enumerated (`0525:a4aa`,
  ping 10.55.0.2 ~0.15 ms), so #9's stricter OTG PMGR acknowledgement holds on
  this hardware.
- ssh was refused: with no `~/.ssh/id_*.pub` on the build host,
  `scripts/add-dropbear.sh` skips dropbear entirely, and `./cascadia build`
  still said `ok: usr/sbin/dropbear` because it grepped the archive's bytes and
  stage 2's text names that path.  The check now reads the archive's entry
  list (`cpio -it`) and also lists `root/.ssh/authorized_keys`.  This tree's
  key lives in the project (`device.env`: `export PUBKEY=...`).
- Second boot, with dropbear: ssh works.  Linux 6.12 on both cores, 470 MB,
  model "Apple iPad mini (iPad2,6)".  OTG(88) reads `0x2ff`: both PMGR
  nibbles ON.  Framebuffer 768x1024 and `/dev/dri/card0`; ALSA "iPad mini 1
  speakers"; battery gauge reads (discharging, as expected).
- Wi-Fi: brcmfmac BCM4334/3 started with USI's `borg-u-st.txt` and scans.
  Bluetooth: `BCM4334B1 37.4 MHz Borg USI` patchram, hci0 up.
- Touch: z2-boot reaches READY with this panel's own calibration.
